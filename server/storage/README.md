# server/storage/ — SQLite 저장과 복구

## 이 폴더는 왜 있나요? (기획안 9절)
농장은 오랫동안 자라는 게임이라 **저장이 날아가면 가장 슬픕니다.** 이 폴더는 농장 상태를 SQLite 파일에 안전하게 저장하고, 저장 도중 컴퓨터가 꺼져도 되살릴 수 있게 하는 역할을 합니다.

## 어떤 기술을 쓰나요?
| 기술 | 의도 |
|---|---|
| SQLite (`sqlite3` 표준 모듈) | 파일 하나로 된 데이터베이스. 서버 설치 없이 표(table)와 SQL을 배울 수 있음 |
| 트랜잭션 (`BEGIN … COMMIT`) | 저장이 "전부 되거나 전부 안 되거나" — 반쯤 저장된 농장이 생기지 않게 함 |
| WAL 저널 모드 | 저장 중 갑자기 꺼져도 DB 파일이 깨지지 않도록 보호 |
| 스냅샷 백업 (최근 N개) | 정상 저장본을 몇 개 보관해 두고, 문제가 생기면 가장 최근의 정상본으로 복구 |
| `schema_version` | 게임이 업데이트되어 표 구조가 바뀌어도 옛 세이브를 새 구조로 옮길 수 있게 함 (마이그레이션) |

## 표(테이블) 초안
| 테이블 | 담는 것 |
|---|---|
| `meta` | 스키마 버전, 마지막 저장 시각, 마지막 실행 시각, 누적 직접 플레이 시간, 게임 속 날짜, 시간 배율 |
| `plots` | 구획 위치, 종류(밭/논/화단), 테두리 색 |
| `crops` | 심은 작물: 품종, 색, 심은 시각, 성장도, 수분 (돌연변이는 6단계) |
| `inventory` | 수확물, 씨앗, 선물, 바이오 연료 |
| `friends` | 친구별 친밀도, 받은 선물 기록 |
| `discoveries` | 도감: 발견한 품종, 신품종 이름, 발견 시각 |
| `task_log` | 작업 기록: 누가(플레이어/친구/자동화) 언제 무엇을 했는지 |
| `integrity` | 저장본의 해시 값 (→ `server/integrity/`) |

## 저장 흐름
```
저장 요청 → 트랜잭션 시작 → 표 갱신 → 해시 계산·기록 → COMMIT
                                                  └─ 정상이면 스냅샷 1개 추가 (오래된 것 정리)
실행 시 → DB 열기 → 파일 검사(PRAGMA integrity_check)
              ├─ 파일이 깨졌으면: 최근 정상 스냅샷으로 복구 → 화면에 "복구했어요" 안내
              └─ 파일은 정상 → 해시 검증 (server/integrity/)
                    └─ 해시 불일치(변조): 복구하지 않고 완전 초기화
```
파일 손상은 사고이므로 복구하고, 해시 불일치는 변조이므로 초기화합니다. 자세한 구분 기준은 [integrity/README.md](../integrity/README.md)를 보세요.

## 경로 원칙
- 세이브 위치는 항상 `프로젝트 폴더/saves/` (상대 경로)
- 경로는 `pathlib.Path`로만 다루고 문자열 이어 붙이기를 하지 않음 → 한글·영어·공백이 섞인 폴더에서도 동작

## 파일
| 파일 | 하는 일 | 상태 |
|---|---|---|
| `schema.sql` | 표 만들기 SQL | ✔ |
| `db.py` | 연결, 표 읽기/쓰기 | ✔ |
| `backup.py` | 스냅샷(최근 5개), 깨진 파일 격리(`saves/broken/`), 복구 | ✔ |
| `store.py` | 위 기능과 해시 검증을 묶어 실행·저장·복구 순서를 관리 | ✔ |
| `migrations.py` | 옛 버전 세이브를 새 표 구조로 옮기기 | ✔ |

### 마이그레이션 (표 구조 버전)
| 버전 | 바뀐 것 |
|---|---|
| 1 | 1~3단계 |
| 2 | 4단계: `plots.border`(테두리 색), `crops.color`(작물 색) 추가 |
| 3 | 시듦 기능 제거: `crops.ripe_minutes`, `crops.withered` 삭제. 시들었던 작물은 수확할 수 있게 되살림 (표를 새로 만들어 옮겨 담는 방식) |

실행할 때 세이브 버전이 낮으면 차례로 올립니다. 옮기기 **전에** 지문을 확인해서, 정상 세이브만 새 지문을 받고 변조된 세이브는 옮긴 뒤에도 "변조"로 남습니다. 더 새로운 버전의 세이브는 열지 않고 안내합니다.

새 농장은 임시 파일(`farm.sqlite.new`)에 다 만든 뒤 이름을 바꿔 넣습니다. 만드는 도중 꺼져도 반쯤 만들어진 세이브가 남지 않아요.
