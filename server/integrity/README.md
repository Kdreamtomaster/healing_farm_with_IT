# server/integrity/ — 해시로 변조 알아채기

## 이 폴더는 왜 있나요? (기획안 8절)
세이브 파일을 몰래 고쳐서 금화를 늘리면 게임의 재미가 사라져요. 이 폴더는 **저장 데이터가 게임 밖에서 바뀌었는지 확인**하고, 바뀌었다면 게임에 알려 줍니다.

> 📌 이것은 **완벽한 보안 장치가 아닙니다.** 내 PC에서 혼자 하는 게임이라 마음먹으면 검사 코드까지 고칠 수 있어요. 목표는 "막기"가 아니라 **해시와 무결성이 무엇인지 이해하고, 변조를 알아채는 규칙을 체험**하는 것입니다.

## 어떤 기술을 쓰나요?
| 기술 | 의도 |
|---|---|
| SHA-256 (`hashlib`) | 데이터가 한 글자만 바뀌어도 완전히 다른 값이 나오는 "데이터 지문" |
| HMAC (`hmac`) + 로컬 비밀 키 | 해시만 쓰면 변조 후 해시도 다시 계산하면 그만. 키를 섞어 "게임이 만든 지문"인지 확인 |
| 정해진 순서로 직렬화 | 같은 내용이면 항상 같은 해시가 나오도록 표/행/열 순서를 고정 |

## 어떻게 동작하나요?
```
저장할 때:  농장 데이터 → 정렬된 JSON → HMAC-SHA256 → integrity 표에 기록
불러올 때:  농장 데이터 → 같은 방법으로 다시 계산 → 기록된 값과 비교
              ├─ 같음  → 정상
              └─ 다름  → "무결성 이상" 상태를 web/에 전달
                          → 메뚜기 떼 연출 후 본 농장 완전 초기화 (web/farm/)
```

### 페널티: 완전 초기화
- 해시가 맞지 않으면 메뚜기 떼가 농장을 휩쓸고 지나가는 연출 후 **본 농장(`saves/farm.sqlite`)을 새 게임 상태로 초기화**
- 초기화 범위: 작물, 구획, 창고, 친구 친밀도, 도감, 플레이 기록 전부
- 연구소 세이브(`saves/lab.sqlite`)는 영향 없음
- 변조가 감지되면 백업으로 되살리지 않음 (백업 복구는 파일 손상 전용)
- 왜 이런 일이 생겼는지 안내 문구와 학습 문서 링크를 보여 줌

### 변조와 파일 손상 구분하기
초기화는 되돌릴 수 없기 때문에, 정직하게 플레이한 사람이 억울하게 초기화되지 않도록 두 경우를 나눕니다.

| 상황 | 판단 방법 | 처리 |
|---|---|---|
| 파일 손상 (저장 중 꺼짐 등) | SQLite가 파일을 열지 못하거나 `PRAGMA integrity_check` 실패 | 최근 정상 백업으로 복구 (`server/storage/`) |
| 변조 | 파일은 정상인데 해시가 다름 | 완전 초기화 |

- 데이터와 해시는 **같은 트랜잭션**으로 기록 → 정상 플레이 중에는 둘이 어긋날 수 없음
- 게임 업데이트로 저장 형식이 바뀔 때는 마이그레이션 후 해시를 다시 계산해 기록

## 연구소와의 관계
연구소(`web/lab/`)는 **별도 세이브 파일**(`saves/lab.sqlite`)을 씁니다. 연구소에서는 데이터를 일부러 바꿔 보고 해시가 어떻게 달라지는지 직접 볼 수 있지만, 본 농장 세이브에는 영향이 없습니다.

## 파일
| 파일 | 하는 일 | 상태 |
|---|---|---|
| `hashing.py` | 정렬된 JSON 직렬화와 HMAC 계산, 키 파일 관리 | ✔ |
| `verify.py` | 불러올 때 비교 → `ok` / `tampered` | ✔ |

- 키 파일은 `saves/.key` 에 처음 실행 시 생성 (Git에 올리지 않음). 키를 지우면 변조로 판단
- 실행할 때마다 바뀌는 `lastLaunchAt` 은 지문 계산에서 제외
- 현재(2단계)는 변조 감지 시 **저장만 잠금**. 메뚜기 떼 연출과 완전 초기화는 7단계에서 구현
