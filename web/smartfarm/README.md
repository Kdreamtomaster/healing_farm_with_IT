# web/smartfarm/ — DAG로 만드는 스마트팜

## 이 폴더는 왜 있나요? (기획안 7절)
농사 작업에는 **순서**가 있어요. 씨앗을 심어야 물을 줄 수 있고, 다 자라야 수확할 수 있죠. 이 폴더는 농사 작업을 **DAG(방향이 있고 되돌아오지 않는 작업 흐름도)** 로 만들어 자동으로 실행하는 스마트팜 기능입니다. 게임을 하며 실제 데이터 파이프라인과 Apache Airflow의 핵심 개념을 체험하는 것이 목표예요.

## 예시 흐름
```
씨앗 심기 → 수분 확인 → 물주기 → 생육 확인 → 수확 → 선물 제작
               │                       │
               └─(충분하면 물주기 건너뜀) └─(덜 자랐으면 나중에 다시 확인)
```

## 담당 기능
| 기능 | 게임 속 모습 | 실제 개념 (Airflow) |
|---|---|---|
| 작업 블록 | "물주기", "수확" 같은 블록 | Task / Operator |
| 화살표 연결 | 블록 사이의 선후 관계 | Dependency (`>>`) |
| 확인 블록 | 수분·생육을 기다렸다가 다음으로 | Sensor |
| 실행 순서 정하기 | 연결된 순서대로 차례 실행 | 위상 정렬, Scheduler |
| 실패와 재시도 | 연료 부족·물 부족으로 실패 → 정해진 횟수 재시도 | retries, 실패 복구 |
| 실행 기록 | 블록마다 성공/실패/건너뜀 색 표시 | Task Instance 상태, 로그 |
| 순환 금지 | 화살표가 빙글 돌아오면 연결 거부 | Acyclic(비순환) 검사 |

## 자동화와 직접 관리의 균형
- 자동화 실행에는 **바이오 연료**가 필요 (연구소에서 만듦 → `lab/`)
- 연료가 한정되어 있어 "무엇을 자동화하고 무엇을 직접 할지" 고민하게 됨

## 어떤 기술을 쓰나요?
| 기술 | 의도 |
|---|---|
| 그래프 자료구조(노드 + 간선 목록) | DAG를 가장 단순한 형태로 표현해 코드로 따라가기 쉽게 |
| 위상 정렬(Kahn 알고리즘) | 선후 관계를 지키는 실행 순서를 계산, 순환 여부도 함께 검사 |
| 상태 기계 (대기/실행/성공/실패/건너뜀) | 작업 하나하나의 상태를 명확히 하여 실패 지점을 바로 알 수 있게 |
| `task_log` 기록 | 실행 이력을 남겨 "어디서 왜 멈췄는지" 되짚어 보기 |

## 들어올 파일 (예정)
- `dag.js` — 노드/간선 정의, 순환 검사, 위상 정렬
- `runner.js` — 실행, 재시도, 상태 관리
- `blocks.js` — 게임 작업 블록 목록 (`farm/` 기능 호출)
- `editor.js` — 블록 연결 화면
