# web/lab/ — 연구소 (샌드박스)

## 이 폴더는 왜 있나요? (기획안 8절)
"세이브를 고치면 정말 들킬까?" 궁금한 마음은 자연스러운 호기심이에요. 연구소는 그 호기심을 **안전하게 실험할 수 있는 별도 공간**입니다. 본 농장은 지키면서, 보안과 무결성을 직접 만져 보며 배울 수 있어요.

## 담당 기능
### 1. 샌드박스 실험
- 연구소 전용 세이브(`saves/lab.sqlite`)와 **연구소 전용 키**(`saves/.lab-key`)에서만 동작 — 본 농장 세이브·키와 완전히 분리
- 실험대에는 연구소 키도 보여 줘요 (공부용 장난감 키). 본 농장 키는 어디에도 보여 주지 않아요
- 작물 값(성장 단계, 색, 크기)을 직접 바꿔 보는 실험대
- 값을 바꾸면 해시가 어떻게 달라지는지 **나란히 보여 주기** (원래 지문 vs 바뀐 지문)
- "해시만 다시 계산하면 속일 수 있을까?" → HMAC 키가 왜 필요한지 체험

### 2. 실험 작물의 규칙
- 연구소에서 실험·변형한 작물은 **주민(친구)에게 선물할 수 없음**
- 대신 **바이오 연료**로 전환 → 스마트팜 자동화(`smartfarm/`)의 연료로 사용
- 농장 → 연구소로 작물을 가져갈 수는 있지만, 연구소 → 농장으로는 연료 형태로만 돌아옴 (한 방향 규칙)

### 3. 송장 번호로 옮기기 (멱등성)
두 세이브 파일에 걸친 옮기기는 한 트랜잭션으로 묶을 수 없어요 (WAL 모드의 SQLite 는 여러 파일에 걸친 트랜잭션이 파일마다만 원자적). 그래서 택배처럼 **송장 번호**를 붙여요.
```
① 연구소: 송장(id, 연료 n개, "보내는 중") 기록 + 실험 작물 빼기   ← 한 트랜잭션
② 농장:   처음 보는 송장 id 면 biofuel += n, 받은 송장 id 기록      ← 한 트랜잭션
③ 연구소: 송장을 "도착"으로                                          ← 한 트랜잭션
```
중간에 꺼져도 다시 켜면 "보내는 중" 송장부터 이어서 하고, 농장은 같은 송장을 두 번 받지 않아요. ([docs/learn/06](../../docs/learn/06-fault-tolerance-and-recovery.md)의 "생각해 볼 문제"와 같은 해결법)

### 4. 서버 주소 (예정)
| 주소 | 하는 일 |
|---|---|
| `GET /api/lab/state` | 연구소 상태 + 정규화 JSON + SHA-256 + HMAC(연구소 키) |
| `POST /api/lab/save` | 연구소 저장 (본 농장과 같은 검증·출처 확인 규칙) |
| `POST /api/lab/import` | 농장 작물 → 연구소 (한 방향) |
| `POST /api/lab/fuel` | 실험 작물 → 바이오 연료 → 농장 (송장 번호) |

## 어떤 기술을 쓰나요?
| 기술 | 의도 |
|---|---|
| 분리된 저장소 (파일 단위 격리) | 샌드박스의 핵심: 실험이 실제 데이터에 닿지 못하게 함 |
| 출처 태그 `origin: "lab"` | 연구소 물건이 선물 등 금지된 곳으로 새는 것을 규칙으로 차단 |
| 허용 목록(allowlist) 변환 | 연구소 → 농장으로 넘어올 수 있는 것은 "바이오 연료" 하나로 한정 |
| 해시 비교 시각화 | 추상적인 해시를 눈으로 보이게 하여 개념 이해를 도움 |

## 꼭 알아 둘 점
연구소의 보안 기능은 **학습과 규칙 이해**를 위한 것입니다. 로컬 싱글 게임에서 변조를 완벽히 막는 수단은 아니라는 점을 화면 안내와 문서에 함께 밝혀요.

## 들어올 파일 (예정, 7단계 — 설계는 [docs/PLAN.md](../../docs/PLAN.md) 7-2 ~ 7-4)
- `server/lab/` — 연구소 세이브·키·송장 처리 (서버 쪽)
- `sandbox.js` — 연구소 세이브 불러오기/저장 (`/api/lab/...`)
- `bench.js` — 값 바꾸기 실험대와 해시 비교 화면
- `biofuel.js` — 실험 작물 → 바이오 연료 전환
