# 08. 시큐어 코딩과 샌드박스

**한 줄 요약** — 안전한 코드는 "들어오는 것은 의심하고, 위험한 실험은 울타리 안에서" 한다.

## 쉬운 비유
농장에 새 비료를 써 보고 싶을 때, 밭 전체에 뿌리기 전에 **작은 시험 화분**에 먼저 써 보죠. 결과가 나빠도 밭은 무사해요. 그 시험 화분이 **샌드박스**입니다.

## 핵심 개념
- **시큐어 코딩** — 처음부터 보안을 생각하며 코드를 쓰는 습관
- **입력 검증** — 밖에서 들어온 값은 믿지 않고 확인. "작물 개수가 -5개?" → 거부
- **허용 목록** — "안 되는 것"을 나열하는 대신 "되는 것"만 정해 두기. 빠뜨린 게 있어도 안전한 쪽으로 실패해요
- **최소 권한** — 필요한 만큼만 허락
- **경로 조작 방지** — `../` 같은 주소로 프로젝트 밖 파일을 읽지 못하게 막기
- **CSRF·DNS 리바인딩 방어** — 다른 웹사이트가 내 브라우저를 시켜 몰래 요청을 보내지 못하게 출처 확인
- **SQL 인젝션 방지** — SQL 문장에 값을 직접 이어 붙이지 않고 `?` 자리표시자 사용
- **샌드박스** — 실험이 바깥에 영향을 주지 못하도록 격리된 공간

## 게임 속에서는
| 원칙 | 적용 | 코드 |
|---|---|---|
| 최소 권한 | 서버는 `127.0.0.1`(내 PC 안)에만 열림. 와이파이의 다른 기기는 접속 불가 | `server/api.py` 의 `make_server` |
| 허용 목록 + 경로 조작 방지 | `web/`, `assets/`, `data/`, `tests/` 안의 파일만. `saves/`, `server/` 는 안 보여 줌 | `server/api.py` 의 `STATIC_DIRS`, `resolve_static` |
| 출처 확인 | `Host`·`Origin` 이 `127.0.0.1`/`localhost` 의 이 포트가 아니면 403 | `server/api.py` 의 `_trusted` |
| 입력 검증 | 저장 요청의 모양·범위·이름 형식 확인. 작물·색·테두리는 데이터 파일에 있는 것만 | `server/validation.py` 의 `validate_save`, `ITEM_ID` |
| 크기 제한 | 1MB 넘는 저장 요청 거부(413) | `server/api.py` 의 `MAX_BODY` |
| 바꿀 수 없는 것 | 저장 요청으로 칸 배치는 못 바꿈 | `store.py` 의 `LayoutMismatch` |
| SQL 인젝션 방지 | 모든 쿼리에 `?` 자리표시자 | `server/storage/db.py` |
| 안전한 화면 | 글자를 HTML 로 해석하지 않는 `el()` (innerHTML 안 씀) | `web/ui/dom.js` |
| 비밀 키 다루기 | 키는 Git 에 올리지 않음, 지문 비교는 `compare_digest` | `.gitignore`, `server/integrity/` |

**보안 결정의 예** — 휴대폰으로 농장에 접속하려면 서버를 와이파이에 열어야 해요. 그러면 같은 와이파이의 누구나 접속을 시도할 수 있어서, 이 기능은 일부러 아직 만들지 않았어요. 편리함과 안전함 사이의 **트레이드오프**예요.

🚧 **7단계 연구소** ([web/lab/](../../web/lab/README.md))
- 연구소는 `saves/lab.sqlite` 와 **자기 키**만 써요. 본 농장 파일·키에는 닿지 않아요 (파일 단위 격리)
- 연구소 → 농장으로 넘어올 수 있는 것은 **바이오 연료 하나뿐** (허용 목록). 연구소 작물로는 선물을 만들 수 없어요

## 실제 제품에서는
- 브라우저는 웹사이트마다 샌드박스를 만들어 한 사이트가 다른 사이트나 내 파일을 건드리지 못하게 해요
- 보안 연구자들은 악성 프로그램을 샌드박스 안에서 실행해 분석해요
- OWASP Top 10(웹 보안 10대 위험)에 입력 검증 실패, 인젝션, 접근 통제 실패가 늘 들어가요

## 직접 해 보기
게임 서버를 켠 채 터미널에서 해 봐요. (Windows PowerShell 에서는 `curl` 대신 `curl.exe`)
1. 🌿 경로 조작 막기: `..` 로 서버 코드를 달라고 해 보기
   ```bash
   curl --path-as-is http://127.0.0.1:8765/web/../server/main.py
   curl http://127.0.0.1:8765/saves/farm.sqlite
   ```
   둘 다 `찾을 수 없어요`. (`--path-as-is` 는 curl 이 `..` 을 미리 정리하지 않고 그대로 보내게 해요)
2. 🌿 다른 웹사이트인 척하기
   ```bash
   curl -X POST http://127.0.0.1:8765/api/save -H "Origin: http://evil.example" -d "{}"
   ```
   → `허용되지 않은 요청이에요` (403)
3. 🌿 이상한 저장 요청 보내기
   ```bash
   curl -X POST http://127.0.0.1:8765/api/save -d "{}"
   ```
   → `state 는 객체여야 해요` (400). 검증 덕분에 세이브는 그대로예요
4. 🌳 `tests/server/test_api.py` 의 `ValidationTest` 를 읽고, "개수에 소수(`1.5`)를 넣으면?" 같은 테스트를 하나 더 만들어 보기
