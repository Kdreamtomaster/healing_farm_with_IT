# 08. 시큐어 코딩과 샌드박스

**한 줄 요약** — 안전한 코드는 "들어오는 것은 의심하고, 위험한 실험은 울타리 안에서" 한다.

## 쉬운 비유
농장에 새 비료를 써 보고 싶을 때, 밭 전체에 뿌리기 전에 **작은 시험 화분**에 먼저 써 보죠. 결과가 나빠도 밭은 무사해요. 그 시험 화분이 **샌드박스**입니다.

## 핵심 개념
- **시큐어 코딩** — 처음부터 보안을 생각하며 코드를 쓰는 습관
- **입력 검증** — 밖에서 들어온 값은 믿지 않고 확인. "작물 개수가 -5개?" → 거부
- **최소 권한** — 필요한 만큼만 허락. 서버는 내 PC(`127.0.0.1`)에서 오는 연결만 받음
- **경로 조작 방지** — `../../` 같은 주소로 프로젝트 밖 파일을 읽지 못하게 막기
- **SQL 인젝션 방지** — SQL 문장에 값을 직접 이어 붙이지 않고 `?` 자리표시자 사용
- **샌드박스** — 실험이 바깥에 영향을 주지 못하도록 격리된 공간
- **허용 목록** — "안 되는 것"을 나열하는 대신 "되는 것"만 정해 두기

## 게임 속에서는
| 원칙 | 적용 |
|---|---|
| 최소 권한 | 서버는 `127.0.0.1`에만 열림 → `server/main.py` |
| 경로 조작 방지 | 파일 요청은 `web/`, `assets/`, `data/` 안쪽만 허용 |
| SQL 인젝션 방지 | 모든 쿼리에 `?` 자리표시자 → `server/storage/db.py` |
| 입력 검증 | 저장 요청의 값 범위·형식 확인 |
| 샌드박스 | 연구소는 `saves/lab.sqlite`만 사용, 본 농장과 분리 → `web/lab/` |
| 허용 목록 | 연구소 → 농장으로는 바이오 연료만 이동, 선물 재료로 사용 불가 |

## 실제 제품에서는
- 브라우저는 웹사이트마다 샌드박스를 만들어 한 사이트가 다른 사이트나 내 파일을 건드리지 못하게 함
- 보안 연구자들은 악성 프로그램을 샌드박스 안에서 실행해 분석
