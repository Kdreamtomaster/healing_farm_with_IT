# 07. 해시와 데이터 무결성

**한 줄 요약** — 해시는 데이터의 지문이다. 지문이 바뀌었다면 데이터도 바뀐 것이다.

## 쉬운 비유
편지를 봉투에 넣고 밀랍 도장을 찍으면, 누군가 몰래 열었을 때 도장이 깨져 알 수 있어요. 해시는 데이터에 찍는 **디지털 밀랍 도장**입니다.

## 핵심 개념
- **해시 함수** — 어떤 데이터를 넣어도 정해진 길이의 값(지문)을 내는 함수
  - 같은 입력 → 항상 같은 지문 / 한 글자만 달라도 → 완전히 다른 지문 / 지문만 보고 원래 데이터를 알아내기는 매우 어려움
- **SHA-256** — 널리 쓰이는 해시 함수 (지문 길이: 16진수 64글자)
- **HMAC** — 비밀 키를 섞어 만든 해시. 키를 모르면 맞는 지문을 새로 만들 수 없음
- **정규화(canonical)** — 같은 내용이면 같은 글자가 되도록 순서를 정해 바꾸기. `{"b":1,"a":2}` 와 `{"a":2,"b":1}` 은 같은 내용이지만 글자가 달라 지문도 달라지거든요
- **서명 범위** — 지문에 들어간 데이터만 지켜져요. 빠진 데이터는 바뀌어도 모름
- **위협 모델** — "무엇으로부터, 어디까지 지킬지"를 미리 정한 표

## 게임 속에서는
```
저장할 때:  meta·칸·작물·창고 → 정렬된 JSON(canonical) → HMAC-SHA256(키: saves/.key) → integrity 표
불러올 때:  같은 방법으로 다시 계산 → 기록된 지문과 비교 → 같으면 ok, 다르면 tampered(변조)
```
- 코드: `server/integrity/hashing.py` 의 `canonical`, `digest`, `load_or_create_key` / `verify.py` 의 `check` (비교는 시간 차이로 힌트를 주지 않는 `hmac.compare_digest`)
- 데이터와 지문은 **같은 트랜잭션**으로 저장 → 정상 플레이 중에는 둘이 어긋날 수 없어요 (`store.py` 의 `save`)
- 서명하지 않는 것: 실행할 때마다 서버가 바꾸는 `lastLaunchAt`, 그리고 작업 기록 `task_log`
- 변조가 감지되면: 저장 잠금 → **무엇이 바뀌었는지** 마지막 정상 스냅샷과 비교해 보여 줌(`integrity/diff.py`) → 메뚜기 떼가 지나간 뒤 본 농장을 처음부터 다시 시작 (`store.py` 의 `reset`). 백업으로 되살리지 않고, 바뀐 세이브와 스냅샷은 `saves/broken/tampered-시각/` 에 남겨 둬요
- 파일이 **깨진 것**(사고)과 **바뀐 것**(변조)은 구분해요. 깨지면 백업 복구(06번 문서), 바뀌면 초기화
- 연구소(`L`)의 **지문 실험대**: 저장된 지문, 다시 계산한 HMAC, 키 없는 SHA-256, "만약 개수를 바꾸면?"의 지문을 나란히 보여 줘요. 브라우저의 Web Crypto 로 계산하고, 서버와 똑같은 지문이 나오는지 테스트로 확인해요 (`web/lab/bench.js`, `tests/web/lab.test.js`)

## 위협 모델: 무엇을 알아채고, 무엇은 못 알아채나
| 상황 | 알아채나요? | 왜 |
|---|---|---|
| 게임 밖에서 세이브 파일의 값을 고침 | ✔ | 지문이 맞지 않아요 |
| 키 파일(`saves/.key`)을 지우거나 바꿈 | ✔ | 새 키로는 옛 지문이 맞지 않아요 |
| 키 파일을 읽어서 지문까지 새로 계산 | ✘ | 키가 같은 PC 에 있어서 막을 수 없어요 |
| 브라우저 개발자 도구로 게임 속 값을 바꿈 | ✘ | 서버에는 게임이 보낸 정상 저장으로 보여요 |
| 작업 기록(`task_log`)을 고침 | ✘ | 서명 범위 밖이에요. 그래서 해금 판단에는 서명된 숫자(`meta.stats`)만 써요 |

이 게임은 내 PC에서 혼자 하는 게임이라 **변조를 완벽히 막는 장치가 아니에요.** 무결성 개념과 규칙을 배우기 위한 장치예요. 진짜로 지켜야 하는 데이터는 사용자가 손댈 수 없는 서버가 키를 갖고 검증해야 해요.

## 실제 제품에서는
- 내려받은 프로그램 파일이 변조되지 않았는지 확인 (체크섬)
- Git은 모든 커밋을 해시로 이름 붙이고, 커밋마다 이전 커밋의 해시를 담아요(해시 체인). 옛 기록 하나만 고쳐도 그 뒤 해시가 줄줄이 바뀌어서 들통나요
- 비밀번호는 원문 대신 (솔트를 섞은) 해시로 저장

## 직접 해 보기
1. 🌿 한 글자 차이, 완전히 다른 지문
   ```bash
   python -c "import hashlib; print(hashlib.sha256('토마토 3개'.encode()).hexdigest()); print(hashlib.sha256('토마토 4개'.encode()).hexdigest())"
   ```
2. 🌿 키가 다르면 같은 내용도 다른 지문 (HMAC)
   ```bash
   python -c "import hmac, hashlib; print(hmac.new(b'my-key', b'tomato 3', hashlib.sha256).hexdigest()); print(hmac.new(b'your-key', b'tomato 3', hashlib.sha256).hexdigest())"
   ```
3. 🌳 변조를 알아채는지 보기 (**프로젝트 폴더를 통째로 복사한 곳에서!** 서버는 끈 채로)
   ```bash
   python tools/sql.py "SELECT count FROM inventory WHERE item = 'seed_tomato'"
   python -c "import sqlite3; db = sqlite3.connect('saves/farm.sqlite'); db.execute('UPDATE inventory SET count = 999 WHERE item = ?', ('seed_tomato',)); db.commit()"
   ```
   서버를 켜면 "세이브 파일이 게임 밖에서 바뀌었어요" 안내에 `inventory.seed_tomato: 4 → 999` 처럼 바뀐 곳이 나와요. **버튼을 누르기 전에** 서버를 끄고 개수를 원래 숫자로 되돌리면? 다시 정상이 돼요. 지문은 "고친 적이 있는지"가 아니라 "지금 내용이 서명한 내용과 같은지"를 보거든요. (버튼을 누르면 메뚜기 떼가 지나가고 그 복사본 농장은 처음부터 다시 시작해요)
4. 🌱 연구소(`L`)의 지문 실험대에서 개수를 하나만 바꿔 보기 → 64글자 중 몇 글자가 달라지나요? 연구소 세이브(`saves/lab.sqlite`)는 게임 밖에서 고쳐 봐도 벌칙이 없어요 ([web/lab/README.md](../../web/lab/README.md))
