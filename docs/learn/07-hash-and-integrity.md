# 07. 해시와 데이터 무결성

**한 줄 요약** — 해시는 데이터의 지문이다. 지문이 바뀌었다면 데이터도 바뀐 것이다.

## 쉬운 비유
편지를 봉투에 넣고 밀랍 도장을 찍으면, 누군가 몰래 열었을 때 도장이 깨져 알 수 있어요. 해시는 데이터에 찍는 **디지털 밀랍 도장**입니다.

## 핵심 개념
- **해시 함수** — 어떤 데이터를 넣어도 정해진 길이의 값(지문)을 내는 함수
  - 같은 입력 → 항상 같은 지문
  - 한 글자만 달라도 → 완전히 다른 지문
  - 지문만 보고 원래 데이터를 알아내기는 매우 어려움
- **SHA-256** — 널리 쓰이는 해시 함수
- **무결성** — 데이터가 허락 없이 바뀌지 않은 상태
- **HMAC** — 비밀 키를 섞어 만든 해시. 키를 모르면 맞는 지문을 새로 만들 수 없음

```
"토마토 3개" → SHA-256 → 7f3a…c21 (예시)
"토마토 4개" → SHA-256 → e90b…4d8 (완전히 다름!)
```

## 게임 속에서는
- 저장할 때 농장 데이터의 HMAC 지문을 함께 기록 → `server/integrity/`
- 불러올 때 다시 계산해 비교 → 다르면 **무결성 이상** + 메뚜기 떼 연출 + 본 농장 완전 초기화
- 단, 저장 중 꺼져 파일이 깨진 것은 변조가 아니므로 백업 복구 — "누가 바꿨나"와 "사고로 깨졌나"를 구분하는 것도 무결성 설계의 일부
- 연구소에서 값을 바꿔 보며 지문 변화를 눈으로 확인

## 꼭 알아 둘 한계 ⚠️
이 게임은 내 PC에서 혼자 하는 게임이라, 마음먹으면 키 파일이나 검사 코드까지 고칠 수 있어요. 그래서 여기의 해시 검증은 **변조를 완벽히 막는 장치가 아니라**, 무결성 개념과 규칙을 배우기 위한 장치입니다. 진짜로 지켜야 하는 데이터는 사용자가 손댈 수 없는 서버에서 검증해야 해요.

## 실제 제품에서는
- 내려받은 프로그램 파일이 변조되지 않았는지 확인 (체크섬)
- Git은 모든 커밋을 해시로 이름 붙여 기록이 바뀌지 않았음을 보장
- 비밀번호는 원문 대신 (솔트를 섞은) 해시로 저장

2. "해시만 다시 계산해서 덮어쓰면 속일 수 있을까?" → HMAC 키가 왜 필요한지 생각해 보기
