# 04. 데이터 파이프라인과 라벨링

**한 줄 요약** — 흩어진 기록을 모으고, 다듬고, 이름표를 붙여야 쓸모 있는 정보가 된다.

## 쉬운 비유
수확한 채소를 그대로 쌓아 두면 쓰기 어려워요. **씻고(정리) → 종류별로 나누고(분류) → 이름표를 붙이고(라벨링) → 상자에 담아야(저장)** 요리에 바로 쓸 수 있죠. 데이터도 같은 과정을 거칩니다.

## 핵심 개념
- **원본 데이터(raw)** — 가공 전 기록. 예: "10:03 플레이어가 3번 칸에 물을 줌"
- **파이프라인** — 데이터가 여러 단계를 차례로 지나며 가공되는 흐름 (수집 → 정리 → 집계 → 활용)
- **집계** — 여러 기록을 합쳐 요약. 예: "오늘 직접 물준 횟수 42번"
- **라벨링** — 데이터에 뜻을 알려 주는 이름표 달기. 인공지능이 배우는 데이터도 사람이 라벨을 붙여 만듦
- **라벨 품질** — 이름표가 틀리면 그 데이터로 내린 판단도 틀림

## 게임 속에서는
| 파이프라인 단계 | 게임 속 모습 |
|---|---|
| 수집 | 모든 작업이 `task_log` 표에 쌓임 |
| 정리 | 연구소(`origin: lab`) 기록, 중복 기록 걸러내기 |
| 집계 | 직접 플레이 시간, 수확 횟수 계산 |
| 활용 | `data/unlocks.json` 조건과 비교해 새 작물 해금 |

**라벨링 체험** — 작물 데이터의 `type`, `water` 라벨은 일괄 물주기의 기준이에요. 돌연변이를 발견해 특징을 확인하고 이름을 붙여 도감에 등록하는 것도 라벨링입니다.

## 실제 제품에서는
- 쇼핑 앱이 "이 상품을 본 사람이 산 상품"을 추천하려면 클릭 기록 파이프라인이 필요
- 자율주행 AI를 위해 사람들이 사진 속 사람·자동차·신호등에 라벨을 붙임
