# 05. 자동화 DAG와 Airflow 개념

**한 줄 요약** — 일의 순서를 화살표로 그린 그림(DAG)이 있으면, 컴퓨터가 순서를 지키며 일을 자동으로 처리할 수 있다.

## 쉬운 비유
라면 끓이기: 물 붓기 → 물 끓이기 → 면 넣기 → 3분 기다리기. 면을 먼저 넣으면 안 되죠. 순서를 화살표로 그리면 누구든(로봇도!) 순서대로 따라 할 수 있어요.

## 핵심 개념
- **DAG** (Directed Acyclic Graph, 방향 비순환 그래프)
  - *Graph* — 점(작업)과 선(연결)으로 된 그림
  - *Directed* — 선에 화살표 방향이 있음 (A 다음 B)
  - *Acyclic* — 빙글 돌아 제자리로 오는 길이 없음 (끝없이 반복하지 않음)
- **위상 정렬** — 화살표를 지키는 실행 순서를 찾는 방법
- **센서(Sensor)** — 조건이 될 때까지 기다리는 작업 ("흙이 마를 때까지 기다리기")
- **재시도(Retry)** — 실패하면 몇 번 더 해 보기

## 게임 속에서는
```
씨앗 심기 → 수분 확인 → 물주기 → 생육 확인 → 수확 → 선물 제작
```
- 스마트팜 편집기에서 블록을 연결해 나만의 DAG 만들기 → `web/smartfarm/`
- 화살표가 순환하면 연결 거부, 연료가 부족하면 실패 → 재시도

## 실제 제품에서는: Apache Airflow
Airflow는 회사에서 "매일 새벽 3시에 어제 매출을 모아 → 정리하고 → 보고서 만들기" 같은 데이터 작업을 DAG로 자동 실행하는 도구예요.

| 게임 | Airflow |
|---|---|
| 작업 블록 | Task (Operator) |
| 블록 연결 | `심기 >> 물주기` |
| 수분 확인 블록 | Sensor |
| 블록 색 (성공/실패) | Task Instance 상태 |
| 재시도 횟수 설정 | `retries=3` |

```python
# Airflow라면 이렇게 쓸 수 있어요 (참고용)
plant >> check_moisture >> water >> check_growth >> harvest >> make_gift
```

## 직접 해 보기
1. 스마트팜에서 "물주기 → 수확 → 물주기"처럼 돌아오는 연결을 만들어 보고 왜 거부되는지 생각해 보기
2. 연료를 일부러 부족하게 두고 실행해 재시도와 실패 표시 관찰하기
