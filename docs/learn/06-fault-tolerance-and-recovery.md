# 06. 내결함성과 데이터 복구

**한 줄 요약** — 문제가 생기지 않게 하는 것만큼, 문제가 생겨도 되살아나게 만드는 것이 중요하다.

## 쉬운 비유
소중한 사진을 휴대폰에만 두면 휴대폰을 잃어버렸을 때 끝이에요. 컴퓨터에 한 장 더 복사해 두면 안심이죠. 농장도 **언젠가 고장 날 수 있다고 가정**하고 대비합니다.

## 핵심 개념
- **내결함성(Fault Tolerance)** — 일부가 고장 나도 전체는 계속 동작하는 성질
- **트랜잭션** — 여러 변경을 "모두 성공 또는 모두 취소"로 묶기. 저장 도중 꺼져도 반쪽짜리 데이터가 남지 않음
- **저널/WAL** — 바꾸기 전에 "무엇을 바꿀지" 먼저 적어 두는 일기장. 꺼졌다 켜지면 일기장을 보고 정리
- **백업/스냅샷** — 정상일 때의 사본
- **멱등성** — 같은 일을 두 번 해도 결과가 같음. 저장 요청이 두 번 와도 문제없게

## 게임 속에서는
| 일어날 수 있는 일 | 대비 |
|---|---|
| 저장 중 PC가 꺼짐 | 트랜잭션 + WAL → 직전 상태 유지 |
| 세이브 파일이 깨짐 | 실행 시 검사 → 최근 정상 스냅샷으로 복구 + 안내 |
| 종료 시 저장 실패 | 5분 자동 저장 + 실행 시 기록으로 손실 최소화 |
| 스마트팜 작업 실패 | 재시도 → 그래도 실패하면 그 지점에서 멈추고 표시 |

관련 코드: `server/storage/backup.py`, `web/smartfarm/runner.js`

## 실제 제품에서는
은행은 송금 중 서버가 꺼져도 "돈은 빠져나갔는데 도착은 안 한" 상태를 만들면 안 돼요. 그래서 트랜잭션, 이중 저장, 장애 복구 훈련을 합니다.

## 직접 해 보기
1. 게임 실행 중 서버 창을 강제로 닫고 다시 켜서 농장이 무사한지 확인
2. `saves/backups/` 폴더에 스냅샷이 몇 개 쌓이는지 관찰
