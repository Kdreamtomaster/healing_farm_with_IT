# 06. 내결함성과 데이터 복구

**한 줄 요약** — 문제가 생기지 않게 하는 것만큼, 문제가 생겨도 되살아나게 만드는 것이 중요하다.

## 쉬운 비유
소중한 사진을 휴대폰에만 두면 휴대폰을 잃어버렸을 때 끝이에요. 컴퓨터에 한 장 더 복사해 두면 안심이죠. 농장도 **언젠가 고장 날 수 있다고 가정**하고 대비합니다.

## 핵심 개념
- **내결함성(Fault Tolerance)** — 일부가 고장 나도 전체는 계속 동작하는 성질
- **트랜잭션** — 여러 변경을 "모두 성공 또는 모두 취소"로 묶기. 저장 도중 꺼져도 반쪽짜리 데이터가 남지 않음
- **WAL(먼저 적어 두기)** — 바꾸기 전에 "무엇을 바꿀지" 따로 적어 두는 일기장. 꺼졌다 켜지면 일기장을 보고 정리
- **원자적 교체** — 새 파일을 옆에 다 만든 뒤 이름만 바꿔 넣기. "바꾸기 전" 아니면 "바꾼 후"만 존재
- **백업/스냅샷** — 정상일 때의 사본
- **격리** — 깨진 파일을 지우지 않고 따로 옮겨 두기. 나중에 원인을 살펴볼 수 있게
- **멱등성** — 같은 요청이 두 번 와도 결과가 같은 성질

## 게임 속에서는
| 일어날 수 있는 일 | 대비 | 코드 |
|---|---|---|
| 저장 중 PC가 꺼짐 | 데이터·작업 기록·지문을 **한 트랜잭션**으로 (`BEGIN IMMEDIATE … COMMIT`, 오류면 `ROLLBACK`) + WAL | `server/storage/store.py` 의 `save`, `db.py` 의 `connect` |
| 새 농장을 만들다 꺼짐 | `farm.sqlite.new` 에 다 만든 뒤 `os.replace` 로 바꿔 넣기 | `store.py` 의 `_new_farm` |
| 세이브 파일이 깨짐 | 실행 시 `PRAGMA integrity_check` → 깨졌으면 `saves/broken/` 으로 격리 → 지문까지 맞는 최근 스냅샷으로 복구 + 화면 안내 | `db.py` 의 `check_file`, `backup.py` 의 `quarantine`, `restore_latest` |
| 백업마저 없음 | 새 농장으로 시작하고 그렇다고 안내 | `store.py` 의 `_recover` |
| 창을 닫으며 저장 | 브라우저에 "창이 닫혀도 끝까지 보내 줘"(`keepalive`) | `web/time/autosave.js`, `web/api.js` 의 `saveState` |
| 저장 요청이 실패 | 보내려던 작업 기록을 다시 줄 세워 다음 저장 때 보냄 | `web/main.js` 의 `save` |

스냅샷은 저장할 때마다 하나씩, 최근 5개만 남겨요 (`backup.py` 의 `KEEP`).

**생각해 볼 문제: "저장은 됐는데 답장을 못 받았다면?"** — 실제로 있었던 일이에요. 창을 닫으며 보낸 저장은 서버에서 끝까지 저장됐는데, 브라우저가 먼저 떠나서 "저장했어요" 답장을 받지 못했어요 (Windows 에서 `ConnectionAbortedError` 로 보여요. 지금은 서버가 조용히 넘어가요 → `server/api.py` 의 `handle_error`).
- 농장 **상태**는 통째로 덮어써서 같은 요청이 두 번 와도 결과가 같아요 → 멱등 ✔
- 작업 **기록**은 덧붙이기라서, 답장을 못 받은 브라우저가 다시 보내면 같은 기록이 **두 번** 쌓여요 → 멱등 ✘
- 해결 아이디어: 기록마다 "송장 번호"(고유 id)를 붙이고, 서버는 이미 받은 번호는 건너뛰기. 연구소 ↔ 농장 옮기기가 바로 이 방법을 써요 → `server/lab/transfer.py`. 두 세이브 파일에 걸친 옮기기는 한 트랜잭션으로 묶을 수 없어서(WAL 모드 SQLite 는 파일마다만 원자적), 받는 쪽이 송장 번호로 "처음 보는 것만" 처리해요. 서버를 켤 때 `recover` 가 끊긴 옮기기를 이어서 하고요

## 실제 제품에서는
은행은 송금 중 서버가 꺼져도 "돈은 빠져나갔는데 도착은 안 한" 상태를 만들면 안 돼요. 그래서 트랜잭션, 이중 저장, 장애 복구 훈련을 합니다. 결제 버튼을 두 번 눌러도 한 번만 결제되게 하는 것(멱등 키)도 같은 생각이에요.

3. 🌳 파일 손상 복구 실험 (**복사본 폴더에서!**): 서버를 끈 뒤 `saves/farm.sqlite` 를 메모장으로 열어 앞부분 글자를 몇 개 지우고 저장 → 서버를 켜면 "최근 백업으로 복구했어요" 안내가 나오고, 깨진 파일은 `saves/broken/` 에 남아 있어요
