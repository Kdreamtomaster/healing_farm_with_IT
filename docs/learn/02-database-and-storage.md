# 02. 데이터베이스와 저장소

**한 줄 요약** — 데이터베이스는 정보를 표로 정리해 두고, 필요한 것을 빠르고 안전하게 꺼내 쓰게 해 주는 창고다.

## 쉬운 비유
농장 일기를 공책에 마구 적으면 "지난주에 심은 감자가 몇 개였지?"를 찾기 어려워요. 날짜·작물·개수 칸이 있는 **표**에 적으면 금방 찾을 수 있죠. 데이터베이스는 그런 표를 여러 개 가진 똑똑한 공책입니다.

## 핵심 개념
- **테이블(표)** — 같은 종류의 정보를 모은 표. 예: `crops` 표에는 심은 작물만
- **행(row)과 열(column)** — 행은 작물 한 그루, 열은 "품종", "심은 시각" 같은 항목
- **SQL** — 표에게 묻는 말. `SELECT * FROM crops WHERE stage = 'ripe';` → "다 자란 작물 모두 보여 줘"
- **SQLite** — 데이터베이스 전체가 **파일 하나**인 가벼운 DB. 휴대폰 앱들도 많이 씀
- **상대 경로** — "C:\Users\..." 처럼 전체 주소 대신 "프로젝트 폴더에서 saves/로" 같은 위치. 폴더를 옮겨도 동작

## 게임 속에서는
- `saves/farm.sqlite` 파일 하나에 농장 전체가 저장됨
- 표 구성은 `server/storage/README.md`의 테이블 초안 참고
- 경로는 `pathlib`로 다뤄 한글 폴더 이름에서도 안전

## 실제 제품에서는
쇼핑몰의 주문, 은행의 계좌, 게임의 랭킹이 모두 데이터베이스에 있어요. 규모가 커지면 PostgreSQL, MySQL 같은 서버형 DB를 쓰지만 **표와 SQL이라는 기본 개념은 같습니다.**

## 직접 해 보기
1. 게임을 실행해 `saves/farm.sqlite`가 생긴 것 확인하기
2. 무료 도구 *DB Browser for SQLite*로 파일을 열어 표 구경하기 (읽기만! 고치면 메뚜기가 와요)
3. `SELECT COUNT(*) FROM crops;` 로 심은 작물 수 세어 보기
