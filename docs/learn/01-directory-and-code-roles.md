# 01. 게임 디렉터리와 코드 역할

**한 줄 요약** — 코드를 역할별 폴더로 나누면, 고칠 곳을 빨리 찾고 한 곳을 고쳐도 다른 곳이 덜 망가진다.

## 쉬운 비유
농장에도 창고, 밭, 작업장이 따로 있어요. 씨앗이 밭 한가운데 흩어져 있으면 찾기 힘들죠. 코드도 **물건마다 정해진 자리**가 있어야 합니다.

## 핵심 개념
- **디렉터리(폴더)** — 파일을 묶는 상자. 이름만 보고 무엇이 들었는지 알 수 있어야 좋은 이름
- **관심사의 분리** — "보여 주기", "규칙 계산", "저장하기"처럼 하는 일이 다른 코드는 떼어 놓기
- **데이터와 코드 분리** — 작물 목록 같은 정보는 코드 밖(`data/`)에 두면 코드를 몰라도 고칠 수 있음

## 게임 속에서는
| 역할 | 폴더 |
|---|---|
| 보여 주기 | `web/ui/`, `assets/` |
| 규칙 계산 | `web/farm/`, `web/time/`, `web/friends/`, `web/smartfarm/`, `web/lab/` |
| 저장하기 | `server/storage/`, `server/integrity/`, `saves/` |
| 기본 정보 | `data/` |
| 확인하기 | `tests/` |

화면에 토마토가 보이기까지: `data/crops.json`(토마토 정보) → `web/farm/`(지금 몇 단계?) → `web/ui/`(어느 그림을 그릴까?) → `assets/crops/tomato_3.png`

## 실제 제품에서는
큰 서비스는 수백 명이 함께 코드를 고쳐요. 폴더 구조가 곧 **"누가 무엇을 책임지는지"의 지도**가 됩니다.

## 직접 해 보기
1. 루트 `README.md`의 폴더 지도를 보고, "선물 반응 대사를 바꾸려면 어느 폴더를 열어야 할까?" 맞혀 보기 (정답: `data/`)
2. 각 폴더의 README 첫 문단만 읽고 한 줄로 역할을 적어 보기
