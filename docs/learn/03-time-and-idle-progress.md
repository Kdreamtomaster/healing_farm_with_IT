# 03. 시간 처리와 방치형 진행

**한 줄 요약** — 게임을 꺼 둔 시간은 "마지막 저장 시각"과 "다시 켠 시각"의 차이로 계산하고, 그 시간을 잘게 나눠 다시 흘려보낸다.

## 쉬운 비유
여행을 다녀오면 "3일 동안 비웠으니 화분 물이 말랐겠다"고 생각하죠. 게임도 **떠난 시각만 기억해 두면**, 돌아왔을 때 무슨 일이 있었을지 계산할 수 있어요.

## 핵심 개념
- **타임스탬프** — 특정 순간을 숫자로 적은 것 (예: 1970년부터 몇 밀리초가 지났는지)
- **경과 시간** — `지금 - 마지막 저장` 
- **틱(tick) 시뮬레이션** — 긴 시간을 한 번에 계산하지 않고 10분씩 잘라 반복 → 중간에 물이 마르는 순간도 놓치지 않음
- **경계 조건** — 이상한 값 대비: 시계를 뒤로 돌려 음수가 되거나, 1년 만에 접속해 너무 클 때 (이 게임은 현실 기준 최대 5일까지만 계산)
- **시간 배율** — 게임 속 시계는 현실보다 빠르게 흐를 수 있음. `게임 시간 = 현실 시간 × 배율`
- **늘 같은 무작위** — 날씨는 날짜와 농장 씨앗으로 계산하는 "의사 난수"라서, 같은 날은 언제 다시 계산해도 같은 날씨예요. 그래서 비운 시간을 나중에 계산해도 그날 비가 왔는지 정확히 알 수 있어요
- **저장 시점 설계** — 언제 저장할지 정하는 것도 설계. 너무 자주 하면 느리고, 드물면 많이 잃음

## 게임 속에서는
- 5분 자동 저장 / 종료 시 저장 / 실행 시 저장 → `web/time/autosave.js`, `server/main.py`
- 게임 날짜와 배율 → `web/time/clock.js` (계절도 게임 날짜를 따름)
- 오프라인 계산과 친구들의 물주기·수확 → `web/time/offline.js`, `web/time/helpers.js`
- 규칙 함수가 `now`를 인자로 받기 때문에, 플레이 중 계산과 오프라인 계산이 **같은 코드**

## 실제 제품에서는
- 모바일 방치형 게임의 오프라인 보상
- 구독 서비스의 "남은 기간" 계산, 배달 앱의 "도착 예정 시각"
- 서버들끼리 시계가 조금씩 달라서 생기는 문제를 다루는 것도 중요한 엔지니어링 주제
