# 구현 계획 (PLAN)

기획안을 실제로 만들기 위한 순서와 결정 사항을 정리한 문서입니다. 코드를 쓰기 전에 **무엇을, 어떤 기술로, 왜** 만드는지 먼저 합의하는 것이 목적입니다.

## 1. 기술 결정

| 결정 | 선택 | 이유 | 검토한 대안 |
|---|---|---|---|
| 실행 구조 | Chrome + 로컬 Python 서버 | SQLite를 **진짜 파일**(`saves/farm.sqlite`)로 저장해야 상대 경로·한글 경로·백업·복구를 눈으로 확인하며 배울 수 있음 | sql.js(브라우저 안 SQLite) + IndexedDB: 설치는 더 쉽지만 저장 파일이 브라우저 내부에 숨어 학습·복구 설명이 어려움 |
| 서버 언어 | Python 3.10 이상, 표준 라이브러리만 사용 (`http.server`, `sqlite3`, `hashlib`, `pathlib`) | 외부 패키지 설치 없이 실행, 초보자에게 읽기 쉬운 언어 | Node.js: JS 하나로 통일되지만 SQLite 모듈 설치(네이티브 빌드)가 필요 |
| 화면 | HTML + CSS + 순수 JavaScript(ES 모듈), `<canvas>` 도트 렌더링 | 빌드 도구 없이 파일을 고치고 새로고침하면 바로 반영 | React/Vite 등: 강력하지만 학습 진입 장벽과 설정 파일이 늘어남 |
| 게임 규칙 위치 | `web/` (브라우저)에 한 곳으로 모음 | 규칙이 두 군데 있으면 서로 어긋남. 서버는 "저장 창구"로 단순하게 유지 | 서버에서 계산: 치팅에 강하지만 로컬 싱글 게임에서는 실익이 적고 코드가 이원화됨 |
| 시간 기준 | 저장 시각은 서버가 기록 (같은 PC의 시계) | 기준 시계를 하나로 통일 | 브라우저 시각만 사용 |
| 그래픽 | 16×16 픽셀 타일, 1개 그림 = 1개 PNG 파일 | 도트를 처음 그리는 사람도 파일 하나만 바꾸면 됨 | 스프라이트 시트 한 장: 성능은 좋지만 수정이 어려움 |

## 2. 단계별 계획

각 단계는 **완료 기준**을 만족하면 다음 단계로 넘어갑니다.

### 0단계 — 문서와 폴더 구조 ✔ 완료
- 폴더 구조, 메인 README, 폴더별 README, 심화 문서 초안 작성
- ✅ 완료 기준: 모든 폴더에 "왜/무엇을/어떤 기술로"가 적힌 README가 있다

### 1단계 — 실행 뼈대와 저장 ✔ 완료
- `python server/main.py` 실행 → Chrome에 빈 농장 화면 표시
- SQLite 스키마 생성, 저장/불러오기 API, 저장 시 해시 기록
- 한글 경로(`D:\게임\힐링농장\`)에서 실행 확인
- ✅ 완료 기준: 저장 → 종료 → 재실행 시 같은 상태가 복원된다
- 구현 메모
  - 파일 손상 시 백업 복구까지 이번 단계에 포함
  - 해시 불일치(변조) 시에는 지금은 **저장만 잠김**. 메뚜기 떼 연출과 완전 초기화는 7단계에서 구현

### 2단계 — 농사 핵심 루프 ✔ 완료
- 심기 → 물주기 → 성장 단계 → 수확, 수분(물기) 수치
- 작물 특징(밭/논/꽃, 물 요구량)별 일괄 물주기
- ✅ 완료 기준: 작물 3종 이상을 처음부터 수확까지 기를 수 있다
- 구현 메모
  - 작물 4종(토마토, 감자, 벼, 튤립), 기본 시간 배율 30
  - 그림은 아직 코드로 점을 찍어 표현 (그림 파일은 4단계)

### 3단계 — 시간과 방치형 진행 ✔ 완료
- 게임 시계: 현실 시간 × 배율(설정 가능)
- 5분 자동 저장, 종료 시 저장, 실행 시 저장
- 오프라인 경과 시간 계산(현실 기준 최대 5일) → 친구들이 물주기·수확 → 로딩 화면 안내 멘트
- ✅ 완료 기준: 시계를 임의로 돌려도(앞/뒤) 게임이 깨지지 않고, 5일 넘게 쉬어도 5일분만 처리되며 결과가 안내된다
- 구현 메모
  - 탭을 숨긴 시간, 컴퓨터 잠자기 등으로 2분 넘게 건너뛴 시간도 비운 시간으로 처리 (창을 켜 둔 채 자리를 비워도 친구들이 돌봄)
  - 친구 3명이 구획 종류별로 담당 (`data/friends.json`). 선물·친밀도는 5단계

### 4단계 — 꾸미기와 그래픽
- 구획별 색 조합(팔레트), 꽃 색상 변형, 게임 속 날짜의 계절에 따른 배경
- ✅ 완료 기준: 구획 색을 바꾸고 저장·복원할 수 있다

### 5단계 — 친구와 나눔
- 선물 레시피(꽃다발, 화분, 손질 재료, 음식), 친구별 취향과 반응
- 숨은 나눔 경험치 → 고급 선물 확률 상승
- ✅ 완료 기준: 같은 선물이라도 친구에 따라 다른 반응이 나온다

### 6단계 — 성장과 발견
- 직접 플레이 시간 누적 → 새 작물 해금
- 수확 시 낮은 확률의 돌연변이 → 신품종 이름 붙여 도감 등록
- ✅ 완료 기준: 도감에 일반/돌연변이 품종이 구분되어 쌓인다

### 7단계 — 무결성과 연구소
- 불러올 때 해시 검증 → 불일치 시 "무결성 이상" 안내 + 메뚜기 떼 연출 + 본 농장 완전 초기화
- 파일 손상(변조 아님)은 백업 복구로 처리 — 초기화와 구분
- 연구소: 별도 세이브 파일에서 변조 실험, 실험 작물 → 바이오 연료
- ✅ 완료 기준: 변조는 초기화, 파일 손상은 복구로 구분되어 처리되고, 연구소에서 바꾼 데이터는 본 농장에 영향을 주지 않는다

### 8단계 — 스마트팜 DAG
- 작업 노드와 선후 관계 편집, 위상 정렬 실행, 실패 시 재시도, 연료 소모
- ✅ 완료 기준: 중간 작업이 실패해도 재시도 후 흐름이 이어지거나 멈춘 지점이 표시된다

### 9단계 — 다듬기와 배포
- 심화 문서를 실제 코드 위치와 연결, 테스트 보강, 첫 릴리스 태그
- ✅ 완료 기준: 처음 보는 사람이 README만 보고 실행·수정할 수 있다

## 4. 확정된 기획 결정

| 항목 | 결정 | 반영 위치 |
|---|---|---|
| 계절 기준 | **게임 속 날짜**를 따름. 게임 시간은 현실 시간 × **배율**(설정 가능)로 흐름 | `web/time/`, `web/decor/` |
| 오프라인 최대 처리 시간 | **현실 시간 기준 5일**. 그 이상은 5일로 잘라 계산 | `web/time/` |
| 친구들의 관리 범위 | 물주기 + 기본 관리 + **수확까지** 대신 해 줌 | `web/time/` |
| 메뚜기 떼 피해 | 해시 불일치(변조) 시 **본 농장 완전 초기화** | `server/integrity/`, `web/farm/` |
| Python 버전 | **3.10 이상** | `server/` |

### 완전 초기화 관련 안전 원칙
- 초기화는 **해시 불일치(변조)** 일 때만 일어남. 저장 도중 꺼져서 파일이 깨진 경우(**파일 손상**)는 변조가 아니므로 백업에서 복구
- 데이터와 해시는 **같은 트랜잭션**으로 기록 → 정상 플레이 중 저장 실패로 해시가 어긋나는 일이 없게 함
- 변조가 감지되면 백업 스냅샷으로 되살리지 않음 (되살리면 페널티가 의미 없어짐)
- 초기화 범위: `saves/farm.sqlite` 전체(도감 포함). 연구소 세이브 `saves/lab.sqlite`는 영향 없음
