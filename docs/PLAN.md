# 구현 계획 (PLAN)

기획안을 실제로 만들기 위한 순서와 결정 사항을 정리한 문서입니다. 코드를 쓰기 전에 **무엇을, 어떤 기술로, 왜** 만드는지 먼저 합의하는 것이 목적입니다.

## 1. 기술 결정

| 결정 | 선택 | 이유 | 검토한 대안 |
|---|---|---|---|
| 실행 구조 | Chrome + 로컬 Python 서버 | SQLite를 **진짜 파일**(`saves/farm.sqlite`)로 저장해야 상대 경로·한글 경로·백업·복구를 눈으로 확인하며 배울 수 있음 | sql.js(브라우저 안 SQLite) + IndexedDB: 설치는 더 쉽지만 저장 파일이 브라우저 내부에 숨어 학습·복구 설명이 어려움 |
| 서버 언어 | Python 3.10 이상, 표준 라이브러리만 사용 (`http.server`, `sqlite3`, `hashlib`, `pathlib`) | 외부 패키지 설치 없이 실행, 초보자에게 읽기 쉬운 언어 | Node.js: JS 하나로 통일되지만 SQLite 모듈 설치(네이티브 빌드)가 필요 |
| 화면 | HTML + CSS + 순수 JavaScript(ES 모듈), `<canvas>` 도트 렌더링 | 빌드 도구 없이 파일을 고치고 새로고침하면 바로 반영 | React/Vite 등: 강력하지만 학습 진입 장벽과 설정 파일이 늘어남 |
| 게임 규칙 위치 | `web/` (브라우저)에 한 곳으로 모음 | 규칙이 두 군데 있으면 서로 어긋남. 서버는 "저장 창구"로 단순하게 유지 | 서버에서 계산: 치팅에 강하지만 로컬 싱글 게임에서는 실익이 적고 코드가 이원화됨 |
| 시간 기준 | 저장 시각은 서버가 기록 (같은 PC의 시계) | 기준 시계를 하나로 통일 | 브라우저 시각만 사용 |
| 그래픽 | 16×16 픽셀 타일, 1개 그림 = 1개 PNG 파일 | 도트를 처음 그리는 사람도 파일 하나만 바꾸면 됨 | 스프라이트 시트 한 장: 성능은 좋지만 수정이 어려움 |

## 2. 단계별 계획

각 단계는 **완료 기준**을 만족하면 다음 단계로 넘어갑니다.

### 0단계 — 문서와 폴더 구조 ✔ 완료
- 폴더 구조, 메인 README, 폴더별 README, 심화 문서 초안 작성
- ✅ 완료 기준: 모든 폴더에 "왜/무엇을/어떤 기술로"가 적힌 README가 있다

### 1단계 — 실행 뼈대와 저장 ✔ 완료
- `python server/main.py` 실행 → Chrome에 빈 농장 화면 표시
- SQLite 스키마 생성, 저장/불러오기 API, 저장 시 해시 기록
- 한글 경로(`D:\게임\힐링농장\`)에서 실행 확인
- ✅ 완료 기준: 저장 → 종료 → 재실행 시 같은 상태가 복원된다
- 구현 메모
  - 파일 손상 시 백업 복구까지 이번 단계에 포함
  - 해시 불일치(변조) 시에는 지금은 **저장만 잠김**. 메뚜기 떼 연출과 완전 초기화는 7단계에서 구현

### 2단계 — 농사 핵심 루프 ✔ 완료
- 심기 → 물주기 → 성장 단계 → 수확, 수분(물기) 수치
- 작물 특징(밭/논/꽃, 물 요구량)별 일괄 물주기
- ✅ 완료 기준: 작물 3종 이상을 처음부터 수확까지 기를 수 있다
- 구현 메모
  - 작물 4종(토마토, 감자, 벼, 튤립), 기본 시간 배율 30
  - 그림은 아직 코드로 점을 찍어 표현 (그림 파일은 4단계)

### 3단계 — 시간과 방치형 진행 ✔ 완료
- 게임 시계: 현실 시간 × 배율(설정 가능)
- 5분 자동 저장, 종료 시 저장, 실행 시 저장
- 오프라인 경과 시간 계산(현실 기준 최대 5일) → 친구들이 물주기·수확 → 로딩 화면 안내 멘트
- ✅ 완료 기준: 시계를 임의로 돌려도(앞/뒤) 게임이 깨지지 않고, 5일 넘게 쉬어도 5일분만 처리되며 결과가 안내된다
- 구현 메모
  - 탭을 숨긴 시간, 컴퓨터 잠자기 등으로 2분 넘게 건너뛴 시간도 비운 시간으로 처리 (창을 켜 둔 채 자리를 비워도 친구들이 돌봄)
  - 친구 3명이 구획 종류별로 담당 (`data/friends.json`). 선물·친밀도는 5단계

### 4단계 — 꾸미기, 그래픽, 소리 ✔ 완료
- 구획별 색 조합(팔레트), 꽃 색상 변형, 게임 속 날짜의 계절에 따른 배경
- 도트 감성 소리: 심기·물주기·수확·저장·돌아왔을 때 효과음, 잔잔한 배경음, 켜고 끄기와 음량 (기본은 효과음만)
- ✅ 완료 기준: 구획 색을 바꾸고 저장·복원할 수 있다
- 구현 메모
  - 테두리 색(구획별), 작물 색(심을 때 선택, 미리보기), 계절(7일마다, 색조·입자)
  - 그림은 16×16 PNG(`assets/crops/`), 열매·꽃 색은 팔레트 스왑
  - 세이브 표 구조 버전 2 (`border`, `color` 추가) — 옛 세이브는 자동으로 옮김
  - 소리는 Web Audio API로 직접 생성 (소리 파일 없음), 소리 설정은 브라우저에 보관
  - 새로고침처럼 1분 미만으로 비운 경우에는 친구들이 수확하지 않도록 조정
  - **시듦 기능 제거** (힐링 게임 원칙: 타이밍 압박 없음). 세이브 표 구조 버전 3, 시들었던 작물은 되살림
  - 물주기 연출 추가: 걸어가는 농부, 드론, 스프링클러, 논 물길 (연출이 칸에 닿을 때 물이 들어감)
  - 심기·수확도 농부가 직접, 바쁘면 친구들이 도우러 옴 (일손 최대 4명)
  - 농장 배경(풀밭·나무·울타리·헛간)과 창고 풍경(쌓이는 수확물, 늘어나는 씨앗 자루)
  - 멍때리기 모드: 농부들이 자동으로 수확·물주기·심기(작물과 색 무작위), 한 번에 최대 3가지 일, 알림 없이 효과음만. 이 시간은 "직접 플레이 시간"에 넣지 않음 (6단계 해금 기준)
  - 반응형: 16:9 PC는 옆 메뉴, 세로 9:16·갤럭시 S25와 좁은 화면은 아래 메뉴 (휴대폰 접속은 서버가 127.0.0.1 전용이라 아직 불가)

### 5단계 — 친구와 나눔 (일부 먼저 진행)
- ✔ 먼저 만든 것: 요리하기(16가지, `data/recipes.json`)와 나눠 먹기(돗자리에 둘러앉아 먹는 연출), 꽃 공방(`data/crafts.json`: 꽃다발·화관·향주머니 선물, 화분·리스·연꽃 등 꾸미기)과 좋아하는 꽃 반응(★/♥)
- 남은 것: 손질 재료·음식 선물, 친구별 반응 대사
- 숨은 나눔 경험치 → 고급 선물 확률 상승
- ✅ 완료 기준: 같은 선물이라도 친구에 따라 다른 반응이 나온다

### 6단계 — 농장 일지와 도감 (데이터 파이프라인 · 라벨링) → 학습 문서 04
배울 것: 원본 → 정리 → 집계 → 활용, 스키마 일관성, 라벨과 라벨 품질, "판단에 쓰는 데이터는 믿을 수 있어야"
- **6-1 기록 정리** — 새 기록부터 모양을 통일: `actor` 는 id(`player`/`haneul`/`idle`/`system`/`smartfarm`), `action` 은 정해진 단어 목록, `detail` 은 JSON(`{"plot":3,"species":"tomato","color":"red"}`). 새 씨앗 선물은 `seed_gift` 로 분리. 옛 기록은 지우지 않고, 일지의 "정리" 단계가 규칙대로 고쳐 읽어요 (학습 문서 04의 "정리가 필요한 진짜 사례")
- **6-2 서명된 집계 숫자** — 해금 같은 판단에는 서명 범위 밖인 `task_log` 대신, 지문이 지켜 주는 `meta.stats`(작물별 수확 수, 만든 요리·선물 수)와 `meta.playSeconds` 를 써요 (학습 문서 07 위협 모델)
- **6-3 농장 일지 화면** (새 탭) — ① 원본 기록 20줄 → ② 정리(고친 줄·버린 줄과 이유) → ③ 집계 표(작물별 수확, 친구별 도움, 시간대별 일) → ④ 해금 진행 막대. 표마다 **그 표를 만든 SQL 문장**을 함께 보여 줘요
  - 서버 `GET /api/journal`: 미리 정해 둔 SQL 만 실행 (브라우저가 SQL 을 보내지 않아요 → 학습 문서 08 허용 목록)
- **6-4 돌연변이** — 수확할 때 낮은 확률(기본 1%, `data/mutations.json`)로 특징이 다른 작물: 색(무지개·반짝·파스텔), 모양(하트·별), 크기(큰·작은). 무작위는 농장 씨앗·칸·심은 시각으로 정해서, 새로고침으로 다시 뽑을 수 없고 테스트로 재현할 수 있어요
- **6-5 도감과 라벨링** — 처음 본 돌연변이는 "특징 이름표"(색·모양·크기)를 골라 달고 이름을 붙여 도감에 등록. 게임은 정답을 알고 있어서 "색은 맞았어요! 모양을 다시 볼까요?"처럼 부드럽게 알려 줘요 (틀려도 벌칙 없음). 도감은 새 표 `discoveries`(서명 범위에 포함, 스키마 버전 4)
- **6-6 해금** — `data/unlocks.json` 의 조건(직접 플레이 시간, 수확 수, 도감 수)을 채우면 새 것이 열려요. 작물 14가지는 지금처럼 처음부터 열어 두고, **해금 대상은 희귀 색과 새 공방·요리 레시피**를 기본안으로 (결정 필요 — 아래 "정해야 할 것")
- ✅ 완료 기준: 일지에서 원본 기록이 집계 표로 바뀌는 과정과 SQL 이 보이고, 도감에 일반/돌연변이 품종이 라벨과 함께 쌓인다

### 7단계 — 무결성 페널티와 연구소 (해시 · 샌드박스 · 위협 모델) ✔ 완료 → 학습 문서 06, 07, 08
배울 것: 변조와 손상의 구분, 서명 범위, HMAC 키의 역할, 격리, 허용 목록, 멱등성
- **7-1 메뚜기 떼와 완전 초기화** (확정된 기획 결정)
  1. 실행 시 지문이 맞지 않으면(`tampered`) 화면에 안내: "세이브 파일이 게임 밖에서 바뀌었어요"
  2. **무엇이 바뀌었는지 보여 주기**: 가장 최근 정상 스냅샷과 비교한 차이(예: `inventory.seed_tomato 4 → 999`). 비교만 하고 되살리지는 않아요
  3. 메뚜기 떼가 왼쪽에서 오른쪽으로 농장을 지나가는 도트 연출 (무섭지 않게, 작물만 사라짐)
  4. `POST /api/reset` — 서버는 지금 상태가 `tampered` 일 때만 받아요. 변조된 세이브와 스냅샷을 `saves/broken/tampered-<시각>/` 으로 옮기고(스냅샷이 남아 있으면 손으로 되살릴 수 있어서) 새 농장을 만들어요. 연구소 세이브는 그대로
  5. 새 농장의 첫 기록: `reset` (이유: 지문 불일치). 학습 문서 07 링크 안내
- **7-2 연구소 샌드박스** — `saves/lab.sqlite` 와 **연구소 전용 키** `saves/.lab-key`. 본 농장 파일·키에는 닿지 않아요. API: `/api/lab/state`, `/api/lab/save`
- **7-3 지문 실험대** — 연구소 물건의 색·크기를 바꾸거나 "만약 개수를 바꾸면?"(저장 안 함)을 넣으면, 정규화 JSON → SHA-256 → HMAC(연구소 키)를 나란히 보여 주고 바뀐 글자를 강조. "키 없이 지문만 다시 계산해 보기" → 검증 실패, "키로 계산" → 통과 → 왜 키가 비밀이어야 하는지, 그런데 왜 같은 PC 의 키는 완벽하지 않은지(위협 모델)
- **7-4 한 방향 규칙과 바이오 연료** — 농장 작물 → 연구소로 보내기는 가능, 연구소 → 농장은 **바이오 연료(`biofuel`)만** (허용 목록). 연구소 물건은 `lab.sqlite` 에만 있어서 선물·요리 재료(농장 창고)와 섞이지 않아요
  - 두 파일에 걸친 옮기기는 한 트랜잭션으로 묶을 수 없어서(WAL 모드의 SQLite 는 여러 파일에 걸친 트랜잭션이 파일마다만 원자적), **송장 번호**를 쓰는 멱등 옮기기: ① 연구소: 송장 기록 + 빼기 ② 농장: 처음 보는 송장이면 연료 더하기 ③ 연구소: 송장 완료. 중간에 꺼져도 다시 켜면 이어서 하고, 두 번 더해지지 않아요 (학습 문서 06)
- ✅ 완료 기준: 변조는 초기화, 파일 손상은 복구로 구분되어 처리되고, 연구소에서 바꾼 데이터는 본 농장에 영향을 주지 않으며, 연료 옮기기가 중간에 끊겨도 두 번 더해지지 않는다

### 8단계 — 스마트팜 DAG (자동화 · Airflow) ✔ 완료 → 학습 문서 05, 06
배울 것: DAG, 위상 정렬, 순환 검사, 센서, 재시도, 실행 조건, 작업 상태, 스케줄
- **8-1 DAG 모양** (JSON) — `{ id, name, schedule: "manual" | "daily@06:00", tasks: [{ id, block, params, retries, retryDelay, trigger }], edges: [[from, to]] }`. 만들면서 바꾼 점: 새 표 대신 농장 세이브의 `meta.smartfarm`(서명 범위)에 DAG·실행 상태·최근 실행 8번을 함께 담았어요. 서버는 `graphlib` 으로 순환까지 검사
- **8-2 블록(Operator)** — `web/farm/` 규칙을 그대로 부르는 블록
  | 블록 | 하는 일 | Airflow 에서는 |
  |---|---|---|
  | 심기 | 칸 종류·작물·색(또는 무작위)으로 빈 칸에 심기 | Operator |
  | 물주기 | 라벨로 고른 칸에 물 (목마른 / 물 많이 먹는 / 논) | Operator |
  | 수분 확인 | 목마른 작물이 없으면 물주기를 **건너뛰게** | BranchOperator |
  | 다 자람 기다리기 | 다 자란 작물이 생길 때까지 30분마다 확인, 하루 지나면 실패 | Sensor (poke, timeout) |
  | 수확 / 요리 / 공방 | 수확, 재료가 있으면 요리·꽃다발 만들기 | Operator |
- **8-3 실행기** — 블록마다 상태: 대기 → 예약 → 실행 중 → 성공 / 건너뜀 / 다시 시도 대기 / 실패 / 앞 단계 실패. 실행 조건은 `all_success`(기본)와 `none_failed`(건너뜀 다음). 같은 계산 함수를 1초 tick 과 비운 시간 계산(10분 조각)에 함께 써요 (학습 문서 03의 "같은 코드로 두 번 쓰기")
- **8-4 연료** — 블록이 실제로 일할 때 바이오 연료 1개(기다리기 블록은 무료). 연료가 없으면 실패 → `retryDelay` 뒤 재시도 → 그래도 없으면 실패 표시하고 멈춤. **작물에게 나쁜 일은 없음** (힐링 원칙)
- **8-5 화면** (자동화 탭 `B`, 틀 3가지 `data/smartfarm.json`) — 블록 목록에서 "앞 작업" 고르기로 화살표 잇기(순환이면 거부하고 도는 길을 보여 줌), 그래프 보기(깊이별 층), 실행 격자 보기(실행 × 블록 색 칸, Airflow Grid 처럼), **"Airflow 코드로 보기"**(내 DAG 를 파이썬 Airflow 코드 모양으로)
- ✅ 완료 기준: 중간 작업이 실패해도 재시도 후 흐름이 이어지거나 멈춘 지점이 표시되고, 순환 연결은 이유와 함께 거부된다

### 힐링 고도화 (단계 사이에 덧붙인 것)
**원칙: 나쁜 일은 일어나지 않는다.** 더 편안하고, 더 예쁘고, 더 살아 있는 농장으로.
- 하루의 흐름: 새벽 → 낮 → 저녁노을 → 밤(별, 헛간 창문 불빛, 화덕 불빛). 밤에도 작물은 똑같이 자람
- 순한 날씨: 맑음, 비(겨울엔 눈), 비 갠 뒤 무지개. 가뭄·폭풍 없음. **비는 작물마다 좋아하는 촉촉함으로 흙을 맞춰 줌**. 날짜와 농장 씨앗으로 정해져서 비운 시간 계산에도 똑같이 적용되고, 돌아왔을 때 "비가 내려 촉촉하게 물을 마셨어요" 안내
- 표정 말풍선: 일하다 콧노래 ♪, 나눠 먹을 때 ♥, 제일 좋아하는 요리면 ★ (`data/friends.json` 의 `favoriteDish`)
- 작은 생명: 헛간 옆 고양이(낮엔 꼬리 살랑, 밤엔 쿨쿨, 누르면 가르릉 ♥), 봄·여름 낮의 나비
- 자연의 소리(설정, 기본 꺼짐): 낮의 새소리, 여름·가을 밤의 풀벌레, 빗소리
- 멍때리기 모드: 재료가 모이면 알아서 요리하고 3분쯤마다 다 같이 나눠 먹기, 밤 10시~새벽 5시에는 다들 쉼(쿨쿨)
- 작물 다양화: 4가지 → 14가지(밭 7·논 3·꽃 4), 요리 8가지 → 16가지. 전부터 키우던 농장에는 "새 씨앗 선물"을 한 번 보냄(`meta.knownSpecies`). 씨앗 고르기는 작물 그림 칸, 부엌은 만들 수 있는 요리 먼저(나머지는 접기)
- 꽃 공방: 꽃 → 꾸미기 물건(마당의 정해진 자리에 저절로, 연꽃 등은 밤에 빛남) / 선물(친구가 걸어와 받고, 좋아하는 꽃이면 ★). 5단계 "선물"의 첫 부분 — 등급·친밀도는 그대로 5단계
- 메뉴와 조작: 탭 메뉴(밭·창고·부엌·공방·설정), 도구 막대, 마우스 끌기·오른쪽 클릭, 키보드 단축키 전부, 메뉴 접기(팝업)·새 창(다른 모니터)
- 아직 안 한 것: 휴대폰 접속(서버를 와이파이에 여는 일이라 보안 결정이 필요)

### 완전 초기화 관련 안전 원칙
- 초기화는 **해시 불일치(변조)** 일 때만 일어남. 저장 도중 꺼져서 파일이 깨진 경우(**파일 손상**)는 변조가 아니므로 백업에서 복구
- 데이터와 해시는 **같은 트랜잭션**으로 기록 → 정상 플레이 중 저장 실패로 해시가 어긋나는 일이 없게 함
- 변조가 감지되면 백업 스냅샷으로 되살리지 않음 (되살리면 페널티가 의미 없어짐)
- 초기화 범위: `saves/farm.sqlite` 전체(도감 포함)와 그 스냅샷(`saves/backups/`). 둘 다 지우지 않고 `saves/broken/tampered-<시각>/` 으로 옮겨 둠 (스냅샷을 남겨 두면 손으로 되살릴 수 있어서). 연구소 세이브 `saves/lab.sqlite`는 영향 없음
- 초기화 전에 "무엇이 바뀌었는지"(최근 스냅샷과의 차이)를 보여 줘서, 왜 이런 일이 생겼는지 이해할 수 있게 함
